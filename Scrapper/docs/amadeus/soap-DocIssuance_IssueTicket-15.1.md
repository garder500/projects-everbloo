# Function: DocIssuance\_IssueTicket

* * *

## 1 Overview

This service is used to **ISSUE** or **REVALIDATE** contracts.

The **ISSUANCE TRANSACTION** is the process whereby the reservation and the pricing information are converted into contracts. **Contracts** are issued for customers buying travel products; those contracts tie the customer to the travel provider (e.g. validating carrier of an airline product). Each contract contains several attributes:

-   _Contract Owner:_ validating carrier

-   _Contract Type__:_ TKT (ticket), MCO (miscellaneous charge order), EMD (electronic miscellaneous document), XSB (excess baggage), TASF (travel agent service fee)

-   _Contract Media__:_ Electronic Paper, Virtual

-   _Contract Nature__:_ Domestic/International

This service can issue only contracts with **TKT CONTRACT TYPE** and **ELECTRONIC/PAPER CONTRACT MEDIA.**This service can issue only contracts with TKT contract type and Electronic/Paper contract media.

To issue MCO, TASF, XSB and EMD contracts, please refer to _DocIssuance\_IssueMiscellaneous service._

To issue MCO, TASF, XSB and/or EMD contracts AND TKT contracts SIMULTANEOUSLY, please refer to _DocIssuance\_IssueCombined service._

The **REVALIDATION PROCESS** is the process allowing the update of certain flight information already printed in a flight coupon or present in an electronic ticket.

### Who can use this service?

This service is addressed to airline and travel agencies willing to issue, re-issue or revalidate air tickets.

### What happens when this service is used?

When the service is used to **ISSUE A TICKET:**

-   The system updates the PNR to add a FA line containing a ticket number and a FB line containing the transaction used and a sequence number.

-   The ticket is stored in Amadeus reporting database.

-   In case of electronic ticket, the ticket is sent to the ETS (Electronic ticket server) of the airline.

-   In case of paper ticket, a print request is sent to the targeted printer.

-   In case of Back Office AIR user, a BO AIR message is sent to the back office system.

When the service is used to **REISSUE A TICKET:**

-   The system updates the PNR to add a FA line containing the new ticket number and a FB line containing the transaction used and a sequence number.

-   The new ticket is stored in Amadeus reporting database.

-   In case of electronic ticket, the new ticket is sent to the ETS (Electronic ticket server) of the airline and the exchanged coupons of the old ticket are flagged as exchanged (E) in the Electronic ticket server.

-   In case of paper ticket, a print request is sent to the targeted printer.

-   In case of Back Office AIR user, a BO AIR message is sent to the back office system.

When the service used to **REVALIDATE A TICKET:**

-   The system updates the PNR to add/update an existing FA line containing a ticket number and an FB line containing the transaction used and a sequence number. The same ticket number as the previous issuance is used (no new ticket is allocated in case of revalidation).

-   In case of electronic ticket revalidation, a revalidation message is sent to the ETS (Electronic ticket server) of the airline to update the history of the ticket.

-   In case of paper ticket revalidation, a print request is sent to the targeted printer to update theticket information.

This service supports several operations. Below is the list of different operations classified by category.

## 1.2 Limitations

Here there are the current limitations that apply to the function:

### Number of Passengers/Pricing Data in one transaction:

If an issuance transaction contains many passengers, many pricing data (TSTs and TSMs) or complex data in the PNR (i.e. remarks), the system can face performance issues and the transaction may end up in a timeout. In order to avoid this kind of issues, it is recommended to split the transaction by 10 PAX.

### Error management with Error codes:

In case of error, the reply sends always the same error code (ERC 120) with the correct error free text information. As a result, in order to perform error management, the error free text must be parsed. For more information, please refer to the section "Receiving a reply". 

## 1.3 Unsupported Operations

Not applicable

## 1.4 Prerequisites

-   The user must be signed in AAA
-   A PNR with passenger and flight information must be present in the AAA context. It can either a retrieved PNR, a displayed PNR from a queue, or a newly created PNR.

The purpose of Alternative Date Validation is to provide the agent the ability to override the current ticketing date, and insert an agent-defined date in an automated ticket. This date will be reflected in the e-ticket display and print.

The ability to use this option is determined by the values of the two following office profile indicators:

The related cryptic option is: ODxxxxxxxx (i.e. TTP/OD23NOV09).

-   BDT (Backdating of Tickets). This field specifies the maximum number of days in the past for which the office can backdate tickets. It is a value between 01 and 90.

## 5.6 Operation: E-ticket Itinerary Receipt

An Electronic Itinerary Receipt (ITR) is a traffic document that is certifiable by the BSP and/or airlines concerned.

The functionality meets the requirements of IATA resolutions 722F and 722 G. It meets also the requirements of ATA resolutions 20.60 and 20.61 for the US market. An Electronic itinerary Receipt is made using the Document Composer Technology.

This service allows the issuance of an ITR simultaneously with the ticket issuance.

**IMPORTANT:** An eticket itinerary receipt request cannot be combined with revalidation request. If done, the ITR request is simply ignored.

The related cryptic option is: ITR (i.e. TTP/ITR)

## 5.36 Operation: Print an Itinerary or Invoice

The service allows requesting the printing of an itinerary or an invoice at issuance time. This functionality isallowed to Central System users only.

The system provides different possibilities to request this operation.

Printing an Itinerary at issuance time.

The user can request to print an itinerary for the traveller. An Amadeus itinerary can contain several informationlike: PNR number, travel agency details, passenger names, service booked (flight and flight services, car hire,hotel reservations, air taxi, tour, cruise…) and other general information.

This service allows the request of different itinerary types:

• IBP - Print Basic Itinerary

• IBJ - Print Basic Joint Itinerary for all passengers

• IEP - Print Extended Itinerary

• IEJ - Print Extended Joint Itinerary for all passengers

To specify the type of itinerary needed, the 3 letter codesets listed above (IBP, IBJ, IEP, IEJ) must be enteredin the <optionGroup> section of the request:

<optionGroup>

<switches><statusDetails\><indicator>IBJ</indicator></statusDetails\></switches></optionGroup>

Printing an invoice at issuance time.

The user can request to print an invoice at issuance time for record keeping and accounting purposes. Two types of invoice exist: Basic and extended. The different between them is that the Basic one includes a basic itinerary and the extended one includes an extended itinerary.

This service allows the request of different invoice types:

• INV - Print Basic Invoice

• IVJ - Print Basic Joint Invoice for all passengers

• INE - Print Extended Invoice

• INJ - Print Extended Joint Invoice for all passengers

• IPE - PNR invoice. Used by BA, with a local credit form of payment (customer specific)

• IPG - GAC invoice. Used by BA, with a global accounting form of payment (customer specific)

To specify the type of invoice needed, the 3 letter codesets listed above (INV, IVJ, INE, INJ, IPE, IPG) must be entered in the <optionGroup> section of the request:

<optionGroup>

<switches><statusDetails\><indicator>IBJ</indicator></statusDetails\></switches></optionGroup>

Printing a mini-Itinerary at issuance time

An ATB mini-itinerary is a set of blank ATB cards containing a compact travel plan for the customer. It can onlybe issued in those markets that are CTS users. In order to request the mini-itinerary issuance, the service mustcontain the option IMP In the <optionGroup> section:

• IMP - Print mini-itinerary

Printing a Wallet-Itinerary at issuance time

A wallet itinerary contains a compact travel plan for the customer. It can only be issued in those markets thatare CTS users. In order to request the mini-itinerary issuance, the service must contain the option IMP In the<optionGroup> section:

• IWP - Print wallet-itinerary

In the example below, a print basic joint invoice for all passengers is requested.

The related cryptic options are: INx, IBx, IEx, IWP, IMP (i.e. TTP/IEJ).
